Code

Three functions

def draw_ground():
    for i in range(20):
        x = i * 40
        pygame.draw.rect(screen, BROWN, (x, 580, 38, 10))

def draw_turret(x):
    pygame.draw.rect(screen, GREY, (x, 540, 20, 40))

def draw_marker(x):
    pygame.draw.circle(screen, RED, (x + 10, 100), 10)

Tidy loop

Game loop becomes simple

while running:
    screen.fill(SKY)

    draw_ground()
    draw_turret(gun_x)
    draw_marker(gun_x)

    pygame.display.flip()

Reads like English: draw ground, draw turret, draw marker.

Concept

Functions share data

draw_turret(gun_x)
draw_marker(gun_x)  # same gun_x!

Marker tracks gun → both use the same gun_x value.

두 함수가 같은 위치를 공유

Concept

Position-aware marker

🎯 ← marker tracks gun
│
▼
🔫 ← gun moves with arrow keys

Marker x = gun x. Move gun → marker follows.

Why split?

Wins of multi-function code

  • Easier to read
  • Easier to debug — find the broken function
  • Each function can be tested alone
  • Reuse in different game modes
⚠️ Watch

Order of drawing

draw_turret()
draw_ground()  # 🚫 ground covers turret!

Pygame draws on top of previous. Background first, foreground last.

⚠ Edge cases

Gotchas + pitfalls

Mutable default trap
Never use def f(x=[]). Use x=None + check inside.
Forgot return?
No return statement = returns None. Easy to miss when tired.
self first
Inside a class method, first param is always self — Python passes it automatically.
Don't shadow builtins
Avoid list = [1,2,3] — you just broke list() for the rest of the file.
