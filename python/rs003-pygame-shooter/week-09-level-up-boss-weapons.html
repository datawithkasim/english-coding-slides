01 MISSILE WHY

Fixing the Missile

The missile weapon already exists, but it's a fake — a slow bullet with a typo'd key ("spash" instead of "splash"), so the splash-damage code that already exists never triggers.

A real missile should also:

01 MISSILE REVEAL ·homing

Steer toward the nearest target

Once per frame, before bullets move, steer any homing bullet toward the closest thing worth hitting:

NEW — homing steer (new code, no OLD counterpart)
for b in bullets:
    if b.get("homing"):
        targets = list(enemies)
        if boss is not None:
            targets.append(boss)
        if targets:
            nearest = min(targets, key=lambda t: (t["x"] - b["x"]) ** 2 + (t["y"] - b["y"]) ** 2)
            if nearest["x"] > b["x"]:
                b["vx"] = min(b["vx"] + MISSILE_HOMING_STRENGTH, 5)
            elif nearest["x"] < b["x"]:
                b["vx"] = max(b["vx"] - MISSILE_HOMING_STRENGTH, -5)
💡 WHAT'S HAPPENING
  • min(targets, key=…) picks the nearest enemy by squared distance.
  • vx nudges by MISSILE_HOMING_STRENGTH each frame — small = lazy curve, big = sharp turn.
  • the min(…, 5) / max(…, -5) cap keeps it from oscillating.
▚ WORKED EXAMPLE — why squared distance, no √
nearest = min by (dx² + dy²)

  enemy A:  dx=30  dy=40    30² + 40² = 2500
  enemy B:  dx=10  dy=70    10² + 70² = 5000

  2500 < 5000  →  A is nearer.  √ gives 50 vs 70.7 — same
  winner, so we skip it. Squaring is cheaper.

03 SQUADRON WHY

Synchronized Squadron Fighters

The fun conceptual twist: you don't need a shared object or a manager class to make enemies move "in sync."

Stamp every enemy in a group with the same spawn frame and use the same movement formula → they automatically stay in lockstep, because math with the same inputs gives the same outputs.

🧠 A concrete intro to derived state vs. stored state.

03 SQUADRON SEE IT

untick "shared clock" → each fighter gets its own clock → the formation falls apart
03 SQUADRON 🤔 FIGURE IT OUT

Move 4 fighters in sync — with no manager class?

  • Q.For 4 enemies to weave together, what must they all share?one clock — a frame counter every member can read.
  • Q.If each computes its x from the same formula and the same time, what do you get?same inputs → same output → they stay in lockstep. No shared object needed.
  • Q.What single number controls how fast they wobble?the multiplier inside math.sin(t * ?).

💡 WHY THEY STAY IN SYNC
  • t = frame_count - spawn_frame is the same for every member (same spawn frame).
  • same t + same formula → same offset → they move as one. No manager object.
  • that's derived state: recomputed each frame, never stored.
▚ WORKED EXAMPLE — the weave, frame by frame
x = col_offset + sin(t · f) · 50        f = wobble constant

f = 0.05  →  full weave every 2π/f ≈ 126 frames (~2s @60fps)
f = 0.15  →  every ≈ 42 frames                  (3× faster)

  t = 0    sin(0.00) =  0.00    x = col +  0    (centre)
  t = 31   sin(1.57) =  1.00    x = col + 50    (far right)
  t = 63   sin(3.14) =  0.00    x = col +  0    (centre)
  t = 94   sin(4.71) = -1.00    x = col - 50    (far left)
