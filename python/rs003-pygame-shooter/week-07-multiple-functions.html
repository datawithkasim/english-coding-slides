Code

Three functions

def draw_stars():
    for i in range(20):
        x = i * 40
        pygame.draw.circle(screen, WHITE, (x, 60), 2)

def draw_ship(x, y):
    pygame.draw.rect(screen, CYAN, (x - 20, y, 40, 50))

def draw_bullet(x, y):
    pygame.draw.rect(screen, YELLOW, (x - 2, y - 8, 4, 12))

Tidy loop

Game loop becomes simple

while running:
    screen.fill(SPACE)

    draw_stars()
    draw_ship(ship_x, ship_y)
    draw_bullet(ship_x, ship_y)

    pygame.display.flip()

Reads like English: draw stars, draw ship, draw bullet.

Concept

Functions share data

draw_ship(ship_x, ship_y)
draw_bullet(ship_x, ship_y)  # same ship_x!

Bullet fires from the ship → both use the same ship_x value.

두 함수가 같은 위치를 공유

Why split?

Wins of multi-function code

  • Easier to read
  • Easier to debug — find the broken function
  • Each function can be tested alone
  • Reuse in different game modes
⚠️ Watch

Order of drawing

draw_ship(ship_x, ship_y)
draw_stars()  # 🚫 stars cover the ship!

Pygame draws on top of previous. Background first, foreground last.

⚠ Edge cases

Gotchas + pitfalls

Mutable default trap
Never use def f(x=[]). Use x=None + check inside.
Forgot return?
No return statement = returns None. Easy to miss when tired.
self first
Inside a class method, first param is always self — Python passes it automatically.
Don't shadow builtins
Avoid list = [1,2,3] — you just broke list() for the rest of the file.
