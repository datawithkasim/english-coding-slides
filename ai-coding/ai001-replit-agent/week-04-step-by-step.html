Break It
Into Steps

Small prompts > one big one

단계별로 나누기

Problem

"Build the whole thing" fails

"Build a complete todo app with login, share, sync, themes"
😵 ...gives up halfway, half-broken

AI loses focus on big tasks. Just like humans!

Solution

Many small prompts

Step 1 → make basic UI
Step 2 → add 'add' feature
Step 3 → add 'delete' feature
Step 4 → add 'check' feature

Each step builds on the last. Solid progress.

Example

Todo app, 4 prompts

[1] "Build a basic todo screen with an
input field, an 'Add' button, and an
empty list below."

[2] "Now make 'Add' actually add the
input value to the list."

[3] "Add an 'X' next to each item to
delete it."

[4] "Add a checkbox to mark items done."
Concept

Each prompt = a small win

  • Run after each step → see progress
  • If broken → fix before moving on
  • Working code accumulates
  • Less overwhelming for you AND AI
Pre-design

List your steps first

Before any prompt → write down 4-6 steps on paper.

1. Login screen
2. Show recipe list
3. Add new recipe
4. Delete recipe
5. Search
Tip

One feature per prompt

✅ "Add an 'X' button to each item that
removes it from the list."

❌ "Add delete, edit, drag-to-reorder,
and undo features."

Smaller bites = better outcomes.

Concept

Why this is easier to debug

If something breaks at step 3 → you know it's tied to step 3.

Compare to: "everything broke after my mega-prompt 😩"

디버깅하기 쉬워요

⚠️ Watch

Don't ask for unrelated steps together

Mixing UI changes with logic changes in one prompt → confused AI.

Stick to one type of change per prompt.

⚠ Edge cases

Gotchas + pitfalls

Test small
Run with a tiny input first. If that breaks, big input won't help.
Read the error
Python tells you the line and the type. Copy the exact text.
One change at a time
If you change three things and it breaks, you don't know which broke it.
Save often
Ctrl-S after every change. Or use a real editor that autosaves.
