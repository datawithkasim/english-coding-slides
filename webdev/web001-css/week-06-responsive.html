Responsive —
Mobile Friendly

Same site. Any size.

반응형 디자인

Problem

Phones ≠ Computers

📱
Phone
~360px wide
💻
Laptop
~1440px wide

Same site needs to look good on both.

Required

The viewport meta tag

<head>
  <meta name="viewport"
        content="width=device-width, initial-scale=1">
</head>

Without this → phone shows tiny zoomed-out site.

반드시 head에 추가!

Concept

% vs px

📏
px
fixed pixels
same on all screens
📐
%
relative to parent
flexes with size

Use % for widths. Use px for fonts (mostly).

Concept

@media queries

/* applies on small screens only */
@media (max-width: 600px) {
  h1 { font-size: 28px; }
}

"Apply these styles when screen is ≤ 600px wide."

화면 크기에 따라 스타일 변경

Watch it!

Media query in action

screen = 400px screen = 1200px
max-width: 600px
h1 { font-size: 28px }
h1 { default size }
▸ Result
small h1 (mobile)
normal h1 (desktop)

조건문 — 화면 크기에 따라

Code

Stack on mobile

.cards {
  display: flex;
  flex-direction: row;  /* PC */
  gap: 16px;
}

@media (max-width: 600px) {
  .cards {
    flex-direction: column;  /* phone */
  }
}

Cards side-by-side on PC, stacked on phone.

Tip

How to test mobile

  • Chrome → Right-click → Inspect → toggle device
  • Resize browser window manually
  • Open on actual phone with Replit URL
Pattern

Mobile-first or desktop-first?

/* mobile-first: defaults are mobile */
.cards { flex-direction: column; }

@media (min-width: 600px) {
  .cards { flex-direction: row; }  /* PC */
}

Either approach works. Pick one and stay consistent.

⚠️ Watch

Tap targets on phone

Buttons must be big enough to tap with a thumb!

.btn {
  padding: 12px 24px;
  font-size: 18px;
}

Apple says: minimum 44×44 pixels.

⚠ Edge cases

Gotchas + pitfalls

Test small
Run with a tiny input first. If that breaks, big input won't help.
Read the error
Python tells you the line and the type. Copy the exact text.
One change at a time
If you change three things and it breaks, you don't know which broke it.
Save often
Ctrl-S after every change. Or use a real editor that autosaves.
